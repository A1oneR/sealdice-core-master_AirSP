# QQ 聊天页误报主程序离线修复（2026-10-13）

用户现场表现为：进入 QQ 聊天页一段时间后，管理页面弹出“主程序离线”；刷新暂时恢复，再次进入聊天页后重复出现。用户确认弹窗期间 QQ 群里的机器人仍能正常回复。

## 复现与原因

实际嵌入的 Vue 管理页面每五秒调用 `/sd-api/baseInfo`，该请求超时为五秒。QQ 聊天页每 2.5 秒读取消息，但旧代码既没有单路请求防重叠，也没有超时取消；未完成的请求仅用序号阻止更新界面，并不会释放浏览器连接。

使用完整的现有前端页面和本地接口模拟，让聊天消息接口持续不返回，保持健康检查接口正常：52 秒内旧版最多积压六个聊天请求，同站点连接被占满，健康检查随后因排队超时而弹出主程序离线。这与现场的“机器人仍能回复、刷新暂时恢复”的表现一致；没有读取远端服务器日志，因此本次证据是本地复现同类故障，而非远端日志确认。

## 修改

- 每类后台读取（会话列表、消息、历史、群资料、图片资源）最多一个进行中的请求。
- 常规消息轮询遇到已有消息或历史读取时跳过本轮，不再叠加请求。
- 消息读取八秒、历史和资源十秒、会话列表十二秒、群资料六秒后取消。计时覆盖 JSON 响应体读取，避免已返回响应头但响应体停滞的请求一直占用连接。
- 切换会话取消旧消息、历史和资料读取；离开聊天路由取消后台读取。
- 浏览器页面进入后台时停止轮询并取消读取，重新可见时恢复轮询。
- 读取超时仍保留已加载的历史；初次加载、资源浏览可提示重试；历史按钮在超时后恢复可点击。
- 原管理页面的离线检测保持工作，真实健康检查失败仍会显示提示，恢复后自动消失。

没有修改 QQ 机器人连接、WebSocket/Webhook、聊天数据库或发送协议。

## 验证

- 修改前对照：六个聊天请求积压，健康检查只到达七次，离线弹窗出现。
- 修复后慢响应体测试：52 秒内聊天请求峰值为一个，健康检查到达十一次，没有误报离线；响应体停滞时也会取消请求。
- 使用完整 Vue 页面模拟健康检查返回 403：离线提示显示；恢复健康检查后提示自动关闭。
- 验证页面不可见时取消请求和停止轮询，重新可见时恢复。
- 既有头像、群资料、双击 @、图片发送、24 个 KaTeX 符号、点击填入指令的浏览器回归通过。
- JS 语法检查通过，独立 EXE 构建成功。

测试脚本为 `scripts/qq-chat-connection.test.cjs`，接口均为本地测试数据。对照记录、截图及修改前脚本位于 `tmp/qq-chat-connection-20261013/`。此次未向真实 QQ 群发送测试消息，也未操作远端正式服务。
